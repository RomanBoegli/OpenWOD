# OpenWOD 1.1.1

Released 26 October 2026.
Image: `ghcr.io/romanboegli/openwod:v1.1.1`, digest to be filled in from the manifest job's summary after it is published.
Database schema version 1, unchanged from 1.1.0.

## What is in it

- Starting a workout on a plain `http://` address, such as a phone on the home network, no longer turns the screen black.
  Browsers offer the id generator the player used only on HTTPS and on localhost, so the first session id threw and the whole page unmounted.
  Ids are now built from a generator every browser provides everywhere.
- Any later error while drawing the app shows its message and a Reload button instead of an empty dark page.
- The container serves HTTPS itself when given a key and a certificate through `HTTPS_KEY` and `HTTPS_CERT`, as a file path or as the PEM text, the way Actual Budget does it.
  The deployment guide walks through a mkcert certificate for the home network, which brings the screen wake lock and the single-tab control to phones without a reverse proxy.
- The release workflow pins the amd64 runner to Ubuntu 24.04, bounds the browser install to ten minutes and caches the browsers, after the install had hung twice on the moving `ubuntu-latest` image.

## Supported browsers

Tested by the automated suite in WebKit, Firefox and Chromium engines.
Safari on macOS and iOS, Firefox and Chrome are the intended browsers.
Web Locks, BroadcastChannel and IndexedDB are required for recovery and single-tab control.
Browsers without them still play workouts, show "Not saving progress on this device", and never claim a recovery.

## Known limitations

- No login.
  Keep the server on a trusted network or behind an authenticating proxy.
- Over plain HTTP the screen wake lock and the single-tab lock are unavailable, because browsers offer them in a secure context alone.
- Session events are uploaded once, with the finished session, not streamed while playing.
- The JSON export can be read but not imported back.
  Restoring is done with the SQLite backup.
- The physical device checks are recorded per release by hand.
- The accent and rest colours, beep level and tone are device preferences, not shared through the household server.

## Upgrading

Set the stack's `APP_IMAGE` to the new tag or digest, re-pull and redeploy.
The schema is unchanged, so no migration runs and the previous image can be chosen again at any time.
