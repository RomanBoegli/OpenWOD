The library's search bar is the same on every screen, and a missing page or workout now says so.
The release workflow creates this release and appends the image digest line at the end of these notes by itself.

## What is in it

- The library shows one search bar on every screen: the search, a Filters button and the shuffle button.
  Filters opens the filter groups and puts the sort box into the bar, with its "Sort" label inside the box, and counts the filters that are on.
  On a phone the sort box takes its own row under the bar.
  The panel stays open or closed as you left it while you move around the app.
- An address the app does not know shows "Page not found", and a link to a workout that is not in the library shows "Workout not found" with its ID.
  Both lead back to the library.
  A link to a saved workout waits for the library to load before it calls the workout missing.
- A confused John Travolta looks around on that page and above "Nothing matches yet" when the filters leave no workout.
  He keeps his transparent background, loads only where he is shown, and stands still when the system asks for reduced motion.
- "Made." in the header's "Not born. Made." carries the accent colour, as it does in the footer.
- The footer's GitHub link reads "Source".
- On a narrow phone the footer no longer lets the page scroll sideways by a few pixels.
- The release workflow checks the live site after a Pages deployment by its version alone: it waits until the site serves the new script and the script carries the tag's version.
- The workout generator moves to version 1.4.0.

## Supported browsers

Tested by the automated suite in WebKit, Firefox and Chromium engines, in both shapes.
Safari on macOS and iOS, Firefox and Chrome are the intended browsers.
Web Locks, BroadcastChannel and IndexedDB are required for recovery and single-tab control, and IndexedDB holds the library in the static site.
Browsers without them still play workouts, show "Not saving progress on this device", and never claim a recovery.

## Known limitations

- A mistyped path outside the app on GitHub Pages, such as `/OpenWOD/foo`, shows GitHub's own 404 page.
  Addresses inside the app, after `#/`, show OpenWOD's.
- Settings follow the last change, with no merging.
- Another device picks up a settings change on reload, focus or reconnect, not while its screen stays open untouched.
- The JSON export carries no settings.
  The SQLite copies under `/data/backups/` and Download backup under Settings → General carry them.
- The static site keeps its library and its settings per browser and per browser profile.
- No login.
  Keep the server on a trusted network or behind an authenticating proxy.
- Over plain HTTP the screen wake lock, the single-tab lock and persistent storage are unavailable, because browsers offer them in a secure context alone.
- The installed web app has no offline copy of itself and needs the server or the site to start.
- Session events are uploaded once, with the finished session, not streamed while playing.

## Upgrading

Set the stack's `APP_IMAGE` to the new tag or digest, re-pull and redeploy.
The database stays at schema version 2, so there is no migration and no pre-migration backup, and a rollback to 1.2.1 needs only the old image.

The static site needs no upgrade: GitHub Pages serves the new release as soon as it is published.
