A Logbook of every session, with delete, bundled workouts that edit like your own, and a clear choice of what happens between two blocks.
The release workflow creates this release and appends the image digest line at the end of these notes by itself.

## What is in it

### Logbook

- Settings → Logbook lists every session played, newest first, with the date, the active time, the score and the Interrupted, Modified and Corrected flags.
  The outcome shows only when it is not Completed.
- Each row can repeat the workout, correct the score or delete the session for good, after a confirmation.
- The clock icon in the header opens the Logbook, and old `#/history` links lead to it.
- A deleted session stays deleted.
  An upload of it still waiting on another device, or a retry, is acknowledged and dropped instead of bringing it back.

### Workouts and the editor

- The workouts that ship with OpenWOD can now be edited, duplicated, exported and removed like your own.
  An edit keeps the workout's place, its id and its past sessions, and Settings → Collections lists removed ones with a Restore button.
- Between two blocks the editor shows one transition tile: Wait for Ready, Rest then continue, or Continue straight away.
- A rest after the last movement of a round is the rest between rounds, and after the last round it is the rest before the next block.
  At the very end of a workout it is dropped.
- Every time field takes mm:ss only, and steps with the mouse wheel and the arrow keys while focused.
  Shift steps a whole minute.
- The interface says "block" and "movement" everywhere, in the editor, the workout page and the session.
- SkiErg is spoken as "Ski air".

### Library and workout page

- Cards and the workout page show the workout's chips above the title: athletes, collection, difficulty and, once done, how long ago.
- A format belongs to a block, so the AMRAP, EMOM or For time chip now sits on each block of the workout page.
  The library filter for it reads "Block format".
- A card shows the description cut to two lines, then the duration, blocks and movements, then the equipment.
- The filters come in the order athletes, collection, difficulty, duration, block format, equipment.
- The workout page puts Start workout, then Edit and Duplicate, then Export and Remove in a compact box beside the description.
- The header shows the running version under the wordmark's lower right corner, on every device, phones included.

### During a session

- A new beep tone: the truck horn.
  At each timed boundary the clock holds for the horn's blast, so "Go" lands at the start of the next movement instead of a second into it.
- The final beep at the end of a workout rings out in full.
- The "Rest" announcement waits for the boundary's cue instead of talking over the next movement, and a manual task no longer says "Go" twice.
- In the focus view the big clock stays in place from one movement to the next.
- The timer colour deepens once over the whole movement and shifts its colour at each warning mark.
- On a phone the movement name gets a line of its own, and the content keeps clear of the coloured ring.

### Bundled workouts

- The full-body partner workout rests 20 seconds between rounds and two minutes between blocks, and runs 48:40.
- HYROX doubles is four blocks, runs and stations taking turns, and runs 13:30.
- The descriptions use the same words throughout: block, movement and, for HYROX, station.

## Supported browsers

Tested by the automated suite in WebKit, Firefox and Chromium engines, in both shapes.
Safari on macOS, iOS and iPadOS, Firefox and Chrome are the intended browsers.
Web Locks, BroadcastChannel and IndexedDB are required for recovery and single-tab control, and IndexedDB holds the library in the static site.
Browsers without them still play workouts, show "Not saving progress on this device", and never claim a recovery.

## Known limitations

- A deleted session cannot be brought back, and the JSON export does not carry the record of deleted sessions.
  A restore keeps the target's record and leaves out the sessions it names.
- An AMRAP with many more movements than three can still need the context view to scroll on a tablet in landscape, and says so with its "Long block" note.
- A mistyped path outside the app on GitHub Pages, such as `/OpenWOD/foo`, shows GitHub's own 404 page.
- Settings follow the last change, with no merging.
- Another device picks up a settings change on reload, focus or reconnect, not while its screen stays open untouched.
- The JSON export carries no settings.
  The SQLite copies under `/data/backups/` and Download backup under Settings → General carry them.
- The static site keeps its library and its settings per browser and per browser profile.
- No login.
  Keep the server on a trusted network or behind an authenticating proxy.
- Over plain HTTP the screen wake lock, the single-tab lock and persistent storage are unavailable, because browsers offer them in a secure context alone.
- The installed web app has no offline copy of itself and needs the server or the site to start.
- Session events are uploaded once, with the finished session, not streamed while playing.

## Upgrading

Set the stack's `APP_IMAGE` to the new tag or digest, re-pull and redeploy.
On the first start the server writes `pre-migration-v2-to-v3-<timestamp>.sqlite` under `/data/backups/`, then adds the table of deleted sessions in one transaction.
`/api/v1/health/ready` then reports `schemaVersion: 3`.
The migration only adds a table, so every workout, session and setting stays as it was.

To roll back to 1.3.1, stop the stack and restore that pre-migration file as `/data/app.sqlite` before choosing the old image.
Sessions played after the upgrade are then lost, so export them first with Export all data under Settings → General if they matter.
A 1.3.x image refuses to start on a version 3 database and says so in its log, rather than misreading the data.

Reload any device that still has the old page open, so it picks up the new build.

The static site needs no upgrade: GitHub Pages serves the new release as soon as it is published, and the browser upgrades its library to IndexedDB version 3 on the first visit.
