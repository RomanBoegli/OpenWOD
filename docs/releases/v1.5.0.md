Write a workout with the AI assistant you already use, keep one spelling per author, and see at a glance where each block stands while you train.
The release workflow creates this release and appends the image digest line at the end of these notes by itself.

## What is in it

### Create with AI

- Create with AI on the library page gives you a guide to copy into any AI assistant, such as ChatGPT, Claude or Gemini.
  It covers the workout file with every option, your movement and equipment names, and two example files, all built from the rules this version enforces.
- Paste the assistant's whole answer back into the same dialog.
  OpenWOD picks the workout file out of the prose and code fences and opens the usual preview, so nothing is saved before you confirm.
- An error shows the lines to paste back to the assistant, with a way back to the answer.
  If a paste does not work, save the YAML part as a `.wod.yaml` file and open it with Import WOD.
- The dialog also downloads the guide as Markdown and the workout file's JSON Schema.
- OpenWOD never contacts an AI service itself.

### Importing

- Save and edit stores a single imported workout and opens it straight in the editor.
  Edit before saving opens it in the editor without storing it.
  A pack still opens the workout's page, or reports what it imported.
- The preview is wider, shows each workout's state as a badge beside its title, and every dialog keeps its button labels on one line, moving a whole button to the next row instead.

### Authors

- Settings → Authors lists every author your workouts name, with how many workouts each.
  New, Rename, Merge (with Undo and Commit) and Delete (with Restore) change what the library shows, searches and suggests.
  Workout files keep their own text.
- The library search finds authors, typos included, and the filters gain an Author group.
- The editor's Author field sits below the title and suggests known authors as you type, with a nudge when a new name is one typo away from a known one.

### During a session

- A round donut beside the clock shows the movements of the round, filling as they go, with a dot per round of the block below it.
  The percentage sits on the other side of the clock, on the same baseline.
- The progress bar is split into one segment per block.
  The top line names the block, the stations heading reads "MOVEMENT 2 / 4", and the state above the clock (Work, Rest, Get ready) is twice as large.
- A card names each block as it starts and fades by itself, and a block waiting for Ready says it is done, with its result.
- When the next movement comes up, the stations shown before slide out and the new ones slide in.
  Reduced motion turns this off.
- The context view keeps the movement under way in the middle of its list on every screen, phones included, while its new Stick to movement switch is on.
- Movements written under another name, such as "Plank rows" for Renegade rows, are announced as written instead of by the record's name.
  The voice packs record the four such names in the bundled workouts, and the device voice reads any other.
- The filler line "Your pace. Keep moving." is gone.

### Library

- The heading's actions move to a row of their own before the heading gets squeezed.

### Bundled workouts and movements

- Dumbbell full body 35 joins the Default collection: a timed warm-up and four dumbbell blocks of two rounds each, 54 workouts in all.
- Six movement records: dumbbell sumo squats, dumbbell pullovers, lateral raises, dumbbell sit-ups, dead bugs and bodyweight good mornings.
- The 22 advanced workouts name "Coach programming" as their author, and their notes keep that the program was shared in a members chat.

### Fixes

- Master data from an older server or an older device cache, without the author fields, no longer stops the app with "OpenWOD hit an error".
- The movement count of a block counts within the current round.

## Supported browsers

Tested by the automated suite in WebKit, Firefox and Chromium engines, in both shapes.
Safari on macOS, iOS and iPadOS, Firefox and Chrome are the intended browsers.
Web Locks, BroadcastChannel and IndexedDB are required for recovery and single-tab control, and IndexedDB holds the library in the static site.
Browsers without them still play workouts, show "Not saving progress on this device", and never claim a recovery.

## Known limitations

- A device still showing 1.4.0 drops author changes when it saves master data (a change to equipment, movements or collections), because it does not know them.
  Reload every device after the upgrade.
- A movement in your own workouts written under another name than its record is read by the device voice, not a recorded one.
- The round donut steps aside on screens too narrow to show it beside the clock, and AMRAP and you-go-I-go blocks have none, because only the athletes know where they are in them.
- A deleted session cannot be brought back, and the JSON export does not carry the record of deleted sessions.
- An AMRAP with many more movements than three can still need the context view to scroll on a tablet in landscape, and says so with its "Long block" note.
- A mistyped path outside the app on GitHub Pages, such as `/OpenWOD/foo`, shows GitHub's own 404 page.
- Settings follow the last change, with no merging, and another device picks up a change on reload, focus or reconnect.
- The JSON export carries no settings.
  The SQLite copies under `/data/backups/` and Download backup under Settings → General carry them.
- The static site keeps its library and its settings per browser and per browser profile.
- No login.
  Keep the server on a trusted network or behind an authenticating proxy.
- Over plain HTTP the screen wake lock, the single-tab lock and persistent storage are unavailable, because browsers offer them in a secure context alone.
- The installed web app has no offline copy of itself and needs the server or the site to start.

## Upgrading

Set the stack's `APP_IMAGE` to the new tag or digest, re-pull and redeploy.
There is no migration: the database stays at schema version 3, and the authors live in the household's master data beside equipment, movements and collections.

To roll back to 1.4.0, choose the old image.
Author renames, merges and deletions made in 1.5.0 are then ignored, and dropped the next time 1.4.0 saves master data.
A JSON export made by 1.5.0 carries the author fields and is refused by 1.4.0, so keep the export made before the upgrade if you may go back.

Reload any device that still has the old page open, so it picks up the new build.

The static site needs no upgrade: GitHub Pages serves the new release as soon as it is published.
